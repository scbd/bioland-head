# Details: 0008. Registry backup posture

## Context

`server/assets/schema.sql` opens with `CREATE DATABASE IF NOT EXISTS i18n_cache` followed by
`USE i18n_cache`, and the runtime default matches (`nuxt.config.ts:63`,
`server/utils/translate/index.js:37`, both `'i18n_cache'`). Everything in that database today is
regenerable: a truncated translation cache costs an AWS Translate bill and some latency, nothing
more. Plan decision 1b puts the registry tables in the same database to avoid new credentials.

That makes the registry the first non-regenerable data in a database whose name says it is
disposable. Losing it is a 404 on every page (see ADR 0006).

## Considered options

1. **A separate database, same server.** Rename the destination so the name carries the meaning —
   a `site_registry` database beside `i18n_cache`. A truncate aimed at translations cannot reach
   config. Cost: `I18N_DB_NAME` currently selects one database for the shared pool, so a second
   database needs either a second variable or cross-database qualified table names, eroding
   decision 1b's "zero new configuration" property.
2. **Same database, documented non-truncatable and backed up (Recommended).** Tables stay in
   `i18n_cache`. The schema file carries a `COMMENT` on each registry table saying it is durable
   config and must not be truncated; the backup covers it; p02-02's seeder is the verified rebuild
   path. Cost: the protection is a convention plus a backup, not a structural boundary — a broad
   `DROP DATABASE i18n_cache` still takes both.
3. **Same database, accepted as risk, debt row only.** No backup change, no rename; p04-04 records
   the exposure and the rebuild procedure. Cost: recovery depends on the seeder and on the
   dmsm JSON5 files still existing, untrue once the decommissioning plan runs.

## Recovery path

Under every option the rebuild is p02-02's seeder: `--env` and `--multi-site-code` are mandatory,
the upsert is keyed on `(env, multi_site_code, site_code)`, and a re-run converges to identical
rows. One slice is the 211-site bl2 set or the 11-site bsl set, so a reseed is minutes of work per
slice, not hours — but it is only as current as the dmsm JSON5 source, and p02-06's drift check
exists precisely because that source can diverge. Last-known-good `biolandSettings` (D-C) and
p02-07's network summary are **not** in the JSON5 files and are not rebuilt by the seeder; they
repopulate on the next successful read and push.

## Consequences

Option 3 requires a p04-04 debt row naming the truncation exposure and the rebuild procedure.
Options 1 and 2 change p02-01's schema destination or its column comments.
