# Details: 0008. Registry backup posture

## Context

`server/assets/schema.sql` creates and uses a database named `i18n_cache`, and the runtime default
matches. Everything in that database today is regenerable: a truncated translation cache costs an
AWS Translate bill and some latency. Plan decision 1b put the registry tables there to avoid new
credentials, which would make the registry the first non-regenerable data in a database whose name
says it is disposable. Losing it is a 404 on every page (see ADR 0006).

## Decision

A separate `site_registry` database beside `i18n_cache` on the same server. `I18N_DB_NAME`
(`nuxt.config.ts:63`, `server/utils/translate/index.js:37`) selects only the pool's default schema,
so cross-database qualified names (`site_registry.sites`) run on that same pool under the same
credentials. Cost is one grant and no new environment variables — decision 1b's "zero new
configuration" property survives intact. At that price it buys a structural boundary instead of a
convention: a truncate or drop aimed at the cache no longer takes the registry with it.

## Consequences

- **p02-01 creates its tables in `site_registry`, not `i18n_cache`.** The schema file creates the
  second database and p02-01 writes qualified table names.
- p04-04 records no truncation-exposure debt row; the boundary removes the exposure.

## Rejected

- **Same database plus a convention.** A `COMMENT` on each registry table saying it is durable
  config, a backup schedule, and p02-02's seeder as rebuild path. The protection is then a comment
  and a backup, not a boundary — a broad `DROP DATABASE i18n_cache` still takes both.
- **Same database, accept the risk, debt row only.** Recovery rests entirely on the seeder, which
  cannot rebuild last-known-good `biolandSettings` (D-C) or p02-07's network summary — neither lives
  in the dmsm JSON5 files, and those files disappear once decommissioning runs.

## Recovery path

The rebuild is p02-02's seeder: `--env` and `--multi-site-code` are mandatory, the upsert is keyed
on `(env, multi_site_code, site_code)`, and a re-run converges to identical rows. One slice is 211
bl2 sites or 11 bsl sites, so a reseed is minutes — but only as current as the dmsm JSON5 source,
which p02-06's drift check exists to catch. Last-known-good `biolandSettings` and p02-07's network
summary are **not** in the JSON5 files; they repopulate on the next successful read and push.
