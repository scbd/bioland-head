# Details: 0006. Degraded-mode policy when site config is unavailable

## Context

`resolveSiteContext` fetches config, and a `null` result throws a 404 with
`Site configuration not found for: ${siteCode}` — `server/utils/context-unified.ts:110-116` on this
branch, cited by the plan as `context-unified.ts:75-81`. The throw is pre-render, so it takes every
route of that site. Once p04-01 deletes the dmsm fallback, that 404 is the whole failure mode.

## Decision

Serve the last-known-good config on a failed read and degrade what the stale payload cannot carry.
The config path already has a 5-minute `cachedFunction` FS cache (`:178-191`,
`CACHE_TTL.FIVE_MINUTES`); a stale entry is served and p02-09's `config.source.fallback` is emitted
with reason `last-known-good-served`.

## Consequences — p03-02's scope

1. **The validate guard must land first.** `fetchDmsmConfigCore` catches transport errors and
   returns `null` (`:168-171`), and `cachedFunction` caches that `null`, overwriting last-known-good
   within one TTL. A `validate: (r) => r !== null` guard — or a rethrow from the catch — is a
   precondition, not a nicety. Without it, reusing the existing cache buys nothing.
2. **Absent and unreachable must be told apart.** Today both return a bare `null` (`:162-165` and
   `:168-171`) and are indistinguishable at the call site. Separating them is new work in p03-02,
   not a property of the current code. `null` must keep meaning 404 for a genuinely absent site, so
   a seeding gap is never masked by a stale serve (p03-02 step 7).
3. **A cold container that never cached the site still 404s.** Accepted residual risk; no task in
   this plan closes it.

p04-01 preserves the policy when it deletes the fallback.

## Rejected

- **Permanent dmsm standby** (registry primary, dmsm on failure). Cheapest degraded mode, but dmsm
  could then never be decommissioned — the goal this plan exists to unblock.
- **Fail closed, keep today's 404.** Free, but a DB blip becomes a total public outage across the
  deployment.
- **Static per-site shell.** A new build artifact plus a second config shape that drifts invisibly.

## Note

No ADR 0005 exists in this repo; the plan's reference to it is aspirational. `GET_LOCK` has zero
code hits here, so it is no precedent.
