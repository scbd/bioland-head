# Details: 0006. Degraded-mode policy when site config is unavailable

## Context

`resolveSiteContext` fetches config, and a `null` result throws a 404 with
`Site configuration not found for: ${siteCode}` — `server/utils/context-unified.ts:110-116` on this
branch, cited by the plan as `context-unified.ts:75-81`. The throw is pre-render, so it takes every route of that
site.

`fetchDmsmConfigCore` returns a bare `null` both when the site is absent (`:162-165`) and when the
fetch throws (`:168-171`) — indistinguishable at the call site.

## Considered options

1. **Fail closed — keep today's 404.** Every URL of every site in the deployment 404s for the whole
   outage. Cheapest: p03-02 and p04-01 change nothing. Cost: a DB blip becomes a public outage.
2. **Serve last-known-good from a stale-tolerant cache (Recommended).** The config path already has
   a 5-minute `cachedFunction` FS cache (`:178-191`, `CACHE_TTL.FIVE_MINUTES`). Extend it to serve a
   stale entry on a failed read, emit p02-09's `config.source.fallback` with reason
   `last-known-good-served`, and degrade what the stale payload cannot carry. **Precondition:
   the resolver must stop collapsing failure into `null`** — add a `validate: (r) => r !== null`
   guard, or rethrow from the catch. Without it `cachedFunction` caches that `null` and overwrites
   last-known-good within one TTL, so reusing the existing cache buys nothing. Cost: that guard, a
   stale-serve branch, a retention decision; a cold container still 404s.
3. **Serve a static minimal shell per site.** A build-time per-site document renders a branded
   holding page. Cost: a new artifact, a build step, and a second config shape to sync.
4. **Keep dmsm as a permanent standby.** Registry primary, dmsm read only on registry failure; the
   fallback stays. Cheapest degraded mode on offer, no new state. Cost: dmsm can then
   never be decommissioned, which is the goal this plan exists to unblock.

**Cost shared by options 2 and 3:** `null` must stay a real answer for a genuinely absent site
(p03-02 step 7 forbids masking a seeding gap), and that distinction does not exist yet: separating
absent from unreachable is new work, not a property of the current code.

## Decision drivers

- Blast radius: the 404 is per-deployment and total.
- No ADR 0005 exists in this repo; the plan's reference to it is aspirational. `GET_LOCK` has zero
  code hits here, so it is no precedent.

## Consequences

p03-02 implements the chosen policy; p04-01 preserves it. Options 1 and 4 each need a p04-04 debt
row: the dark-deployment risk, or dmsm's indefinite life.
