# Details: 0002. Resolve a custom redirect Host to its siteCode with a cached DMSM reverse index

## Context

Every resolver in bioland-head takes the first label of the request Host as the siteCode
(`server/utils/context-unified.ts:194-207`, `app/plugins/site.js:164-180`,
`app/middleware/02.bioland.global.js:374-378`). DMSM can set a per-Site `redirect`, a bare
hostname such as `chm.example.gov`, which in production replaces the generated Host
`https://{siteCode}.{baseHost}`. A request arriving on that redirect Host cannot be mapped back
to its siteCode today: it would resolve to `chm`, or fail closed with 400.

DMSM exposes only per-site (`/config/{env}/{multiSiteCode}/{siteCode}`) and all-sites
(`/config/{env}/{multiSiteCode}`) endpoints, no by-host lookup. The all-sites endpoint is already
called unauthenticated from `server/api/chm-network/index.js:3-8`. Per-site config is cached 300
seconds with Nitro's `cachedFunction` (`server/utils/context-unified.ts`), the same pattern the
new reverse index reuses.

## Considered options

1. **Static env-var map of redirect hosts to site codes.** Rejected: duplicates DMSM, which is
   the source of truth for Site config, and needs a redeploy for every new domain.
2. **Edge-injected `x-site-code` header from Traefik.** Rejected: depends on per-site traffic
   config that does not exist yet in DMSM or infra, and adds a new trusted header to validate.
3. **A new DMSM by-host endpoint.** Cleanest payload, but blocks bioland-head on a cross-repo
   change. Kept as the future replacement; the single-function seam in the decision exists so
   this can swap in later without touching callers.

## Consequences

- One extra DMSM round trip per pod every 300 seconds, only when custom hosts are in use.
- A newly configured redirect host is recognized within 300 seconds.
- A DMSM outage degrades custom-host resolution to 400 while generated `*.{baseHost}` hosts keep
  working.
- The all-sites payload grows with the network (hundreds of Sites), so the fetch must select only
  `siteCode` and `redirect` from each entry, not the full per-site config.
- Only non-`*.{baseHost}` hosts consult the index; they never fall back to first-label parsing.
- `docs/prd.md:138-139,201` and `docs/architecture.md:335` ("a request resolves to exactly its
  Site, or fails closed") describe tenancy as failing closed on any host that is not
  leading-subdomain shape. The task that wires this in must amend both to describe the redirect
  Host path.
