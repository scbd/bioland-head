# Details: 0009. Cutover soak window and fallback threshold

## Context

OPS-1 flips `NUXT_PUBLIC_CONFIG_SOURCE=registry` one deployment at a time, dev then stg then prod,
and its pass/fail gates p04-01. The window and threshold are authored here deliberately: a gate must
not set the bar it is judged against.

p02-09 emits `config.source.fallback` per event with `siteCode`, `env`, `multiSiteCode`,
`servedFrom`, a timestamp, and a `reason` from a fixed enum: `registry-unreachable`,
`registry-row-malformed`, `site-absent-from-registry`, `drupal-unreachable`,
`last-known-good-served`. It also keeps a counter on a diagnostics route.

**That counter has no denominator.** It is keyed `env:multiSiteCode:siteCode:reason`, is
per-container, counts fallbacks but never total reads, and resets on restart. A percentage fallback
rate is therefore unanswerable by the instrument OPS-1 will actually have — only an absolute count
over a window.

## Decision

An error budget with a shape test. `site-absent-from-registry` must be zero: that is a seeding
defect, not a blip, so one event fails the slice. `registry-unreachable` and `last-known-good-served`
share a budget of at most five fleet-wide per window, **with no two events inside one 5-minute
window** — `last-known-good-served` is ADR 0006's stale-serve outcome of that same registry failure,
so budgeting it separately (or not at all) would let stale configuration serve throughout the soak
while OPS-1 records zero failures. The budget tolerates scattered blips; the shape test fails a
cluster, which is what an outage looks like.

| Slice | Window | Reasoning |
|---|---|---|
| dev | 24 hours | One traffic cycle, cheap to repeat. |
| stg | 48 hours | Two cycles, ideally crossing a weekend. |
| prod | 72 hours | Crosses a container recycle and a scheduled re-seed (p02-06). |

## The query

Group `config.source.fallback` records by `reason` over the window, filtered to the flipped `env`,
compare against the budget, and check the largest count in any 5-minute bucket. Normalising per
site-day is an equivalent alternative. Baseline before the flip and measure the delta, not the
lifetime total. The per-container diagnostics route is a secondary signal only, because it resets on
restart.

## Rejected

- **Zero tolerance, or a fleet-wide cap of one.** Simplest and strictly safest, but across 211 bl2
  sites over 72 hours one transient error restarts a prod soak, pressuring the operator into
  relaxing the bar mid-run — the failure mode this ADR exists to prevent.
- **Percentage rate against total reads.** The instinctive shape, but it needs a total-config-read
  counter p02-09 does not emit, putting a follow-up PR on the critical path to the prod flip.
