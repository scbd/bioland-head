# Details: 0007. Per-environment config database topology

## Prerequisite, independent of the ruling

`I18N_DB_CONNECTION_LIMIT` defaults to 5 (`nuxt.config.ts:64-66`,
`server/utils/translate/index.js:38`) and must be raised before the first flip, since config reads
join the translation workload on one pool. A deployment action, not a code change; it gates OPS-1
under every option below.

## Context

Every connection value is an environment variable resolved at runtime
(`nuxt.config.ts:57-66` → `server/utils/translate/index.js:33-40`). Nothing here records which
server a deployment points at, so the topology is an operator fact. This ADR names the variables
only; no host, credential, or connection string appears in this repo.

Plan decision 6 scopes the registry to one `env` x `multiSiteCode` deployment and calls that the
tightest blast radius. That holds only if the environments do not share a server — and we cannot
decide a topology we do not control, so this ADR recommends a mechanism, not a fact.

## Considered options

1. **Distinct server per environment.** A mistake reaches one environment only, and a dev re-seed
   cannot corrupt a prod flip. Cost: nothing new. But this is the operator's state to report, not
   ours to choose.
2. **Apply a hard `WHERE env = ?` read filter unconditionally (Recommended).** Treat `p02-01`'s
   `env` column as load-bearing on every registry read, whatever the operator answers. Correct under
   either topology: on a shared server it is the isolation, on distinct servers a no-op predicate.
   A missing filter silently serves prod a dev row, so it is tested either way. Cost: one predicate
   and its test. p02-01 and p02-02 proceed today; the operator's answer becomes an optimisation,
   not a gate.
3. **Distinct server, plus a separate `CONFIG_DB_*` variable set.** Strongest isolation — config
   reads stop sharing the translation pool. Cost: new operator-supplied variables and credentials,
   and it drops plan decision 1b's "zero new infrastructure" property.

## Decision drivers

- p02-01 step 3 already keeps `env` columns "as the only defense if a DB is ever shared", so option
  2 is a hardening of the drafted shape, not a redesign.
- Option 3 interacts with pool contention (C13): config reads inherit the shared
  `acquireTimeout: 30000` from `createPool`.

## Consequences and manual action

If option 3 is ruled, a `CONFIG_DB_HOST` / `_PORT` / `_USER` / `_PASSWORD` / `_NAME` /
`_CONNECTION_LIMIT` set must be added by hand per environment. Values are operator-supplied. No task
in this plan writes a `.env*` path (Plan Rule 26).
